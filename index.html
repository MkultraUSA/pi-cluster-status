My Raspberry Pi cluster patches itself now

I run a 4-node Raspberry Pi Kubernetes cluster in my house. I got tired of reading CVE advisories and wondering which of my machines they applied to, so I taught the cluster to do that reading itself. This page is generated by the cluster. Every hour it scans every image it runs, publishes what it found, and if a fix exists upstream — it patches itself and you can read about it in the timeline below.

How it works

Every hour a scanner (trivy, with its CVE database auto-refreshed) checks each image in my registry. When a fix exists upstream, the verdict on that image flips to REBUILD+REPLACE DUE. That verdict wakes the actuator: it rebuilds the image in place with Debian's security patches and the affected pip packages upgraded, commits the new tag to git, and ArgoCD rolls it out across the nodes behind readiness checks. A security analyst agent reads anything unusual and writes what it decided into a playbook. I only step in for the risky stuff — Kubernetes upgrades and major version bumps.

Why the urgency? In October 2026 two critical PHP remote-code-execution bugs (nicknamed PHP2Shell) were being exploited four days before the fix was released. Working exploits showed up within hours of the patch, and a week later most sites still hadn't updated. The bad guys work in hours now. So does this cluster.

What I'm still figuring out

The first rebuild I did tonight didn't actually clear the two fixable CVEs. The scanner caught it — turns out they were hiding inside setuptools' own vendored copy of wheel, not the packages I upgraded. Recipe v4 upgrades setuptools too. I left the failed attempt in the timeline on purpose. A scanner that can't tell you your patch didn't work is worse than no scanner.
